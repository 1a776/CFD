本文说明第 1 题线性对流方程在当前项目中的统一工作方式。

当前已经实现两个配置：

```text

    结构化四边形网格 + Gauss upwind

02_sine_wave_quad_linearUpwind
    结构化四边形网格 + Gauss linearUpwind grad(T)
```

配置文件位于：

```text
scripts/configs/
```

旧的案例脚本目录已经删除：

```text
scripts/01_sine_wave_quad/

```

现在所有案例统一通过顶层脚本执行。

## 2. 配置文件和案例目录的关系

`01` 配置：

```text
scripts/configs/01_sine_wave_quad_upwind.json
```

控制：

```text
cases/01_sine_wave_quad/
```

并写入一阶迎风格式：

```foam
div(phi,T)      Gauss upwind;
```

`02` 配置：

```text
scripts/configs/02_sine_wave_quad_linearUpwind.json
```

控制：

```text
cases/02_sine_wave_quad_linearUpwind/
```

并写入：

```foam
gradSchemes
{
    default         Gauss linear;
    grad(T)         Gauss linear;
}

divSchemes
{
    default         none;
    div(phi,T)      Gauss linearUpwind grad(T);
}
```

因此，案例、网格分辨率、插值格式和时间参数都来自同一个 JSON 配置文件。

## 3. N 的含义

当前结构化四边形网格使用：

```text
hex (0 1 2 3 4 5 6 7) (N N 1) simpleGrading (1 1 1)
```

因此：

| 目录 | x 单元数 | y 单元数 | 总单元数 | 近似网格尺度 |
|---|---:|---:|---:|---:|
| `N10` | 10 | 10 | 100 | 0.1 |
| `N20` | 20 | 20 | 400 | 0.05 |
| `N40` | 40 | 40 | 1600 | 0.025 |
| `N80` | 80 | 80 | 6400 | 0.0125 |

`N` 是每个方向的单元数，不是总单元数。

## 4. 只准备一个 N

准备 01 的 `N40`：

```bash
python3 scripts/prepare_case.py \
    --config scripts/configs/01_sine_wave_quad_upwind.json \
    --N 40 \
    --overwrite
```

准备 02 的 `N40`：

```bash
python3 scripts/prepare_case.py \
    --config scripts/configs/02_sine_wave_quad_linearUpwind.json \
    --N 40 \
    --overwrite
```

这个命令会：

1. 读取 JSON 配置；
2. 找到对应案例的 `N20` 模板；
3. 创建或重建目标 `N40`；
4. 修改 `blockMeshDict` 中的 `(N N 1)`；
5. 修改 `fvSchemes` 中的 `div(phi,T)`；
6. 修改 `controlDict` 中的 `application`、`endTime` 和 `maxCo`；
7. 根据单元中心生成 `0.orig/T`；
8. 写入 `metadata.json`、`Allrun` 和 `Allclean`。

它不会执行 `blockMesh`、`checkMesh` 或学生求解器。

如果只想重新生成已有案例的初始场：

```bash
python3 scripts/prepare_case.py \
    --config scripts/configs/01_sine_wave_quad_upwind.json \
    --N 40 \
    --refresh-initial-only
```

## 6. 运行一个 N

```bash

    --config scripts/configs/01_sine_wave_quad_upwind.json \
    --N 40 \
    --overwrite
```


如果案例已经准备好，只运行：

```bash

    --config scripts/configs/01_sine_wave_quad_upwind.json \
```

如果只想运行、不生成单 N 图：

```bash

    --config scripts/configs/01_sine_wave_quad_upwind.json \
    --N 40 \
    --no-postprocess
```

## 10. 计算收敛阶

```bash
python3 scripts/analyze_study.py \
    --config scripts/configs/01_sine_wave_quad_upwind.json
```

脚本读取：

```text
data/analysis/01_sine_wave_quad/raw_results.csv
```

并写出：

```text
data/analysis/01_sine_wave_quad/convergence_summary.csv
data/analysis/01_sine_wave_quad/analysis.md
```

网格误差的计算公式为：

$$L_1=\frac{\sum_c V_c|T_c-T_c^{exact}|}{\sum_c V_c|T_c^{exact}|}.$$

观察收敛阶为：

$$p=\frac{\log(E_N/E_{2N})}{\log(2)}.$$

例如：

```text
observedOrderL1(N20) = log(L1_N10 / L1_N20) / log(2)
observedOrderL1(N40) = log(L1_N20 / L1_N40) / log(2)
observedOrderL1(N80) = log(L1_N40 / L1_N80) / log(2)
```

实际代码位置：

```text
scripts/common/advection_tools.py
    normalized_errors()

scripts/common/study_analysis.py
    observed_order()
    analyse()
```

## 12. 不同 N 的代码哪里不一样

不同 N 的核心区别在：

```text
cases/<caseName>/Nxx/system/blockMeshDict
cases/<caseName>/Nxx/0.orig/T
```

`blockMeshDict` 的核心行：

```text
hex (0 1 2 3 4 5 6 7) (N N 1) simpleGrading (1 1 1)
```

`0.orig/T` 的数据个数等于：

```text
N * N
```

例如：

```text
N20: 400 个标量
N40: 1600 个标量
```

这些值由：

```text
scripts/common/advection_sine.py
scripts/common/advection_tools.py
```

根据单元中心坐标生成：

$$T(x,y,0)=\sin(2\pi(x+y)).$$

不要把 `N20/0.orig/T` 直接复制给 `N40`。

## 13. 不同格式哪里不一样

不同空间格式主要由 JSON 中的：

```text
divScheme
gradTScheme
```

控制。

准备案例时，脚本会把它写入：

```text
cases/<caseName>/Nxx/system/fvSchemes
```

核心实现位置：

```text
scripts/common/foam_case.py
    _patch_fv_schemes()
```

求解器代码中只调用：

```cpp
fvc::div(phi, T, "div(phi,T)")
```

OpenFOAM 会根据 `fvSchemes` 中的 `div(phi,T)` 查找实际格式。

## 14. 修改初始函数、速度或 CFL

### 修改初始函数

正弦波初始场由：

```text
scripts/common/advection_sine.py
```

间接调用：

```text
scripts/common/advection_tools.py
    exact_values()
    write_initial_field()
```

注意：初始场和精确解必须同步修改，否则误差没有意义。

### 修改插值格式

优先修改或新增：

```text
scripts/configs/*.json
```

不要手工逐个改每个 N 的 `fvSchemes`，否则容易造成不同 N 使用不同格式。

### 修改 CFL 或终止时间

优先修改 JSON 中的：

```text
maxCo
endTime
```

然后重新准备对应案例：

```bash
python3 scripts/run_study.py \
    --config scripts/configs/01_sine_wave_quad_upwind.json \
    --prepare-only \
    --overwrite
```

## 15. 清理单个 N

只清理 01 的 `N40`：

```bash
sh cases/01_sine_wave_quad/N40/Allclean
```

它会删除可重新生成的：

```text
0/
constant/polyMesh/
数值时间目录
postProcessing/
log.*
run.batch.log
```

它会保留：

```text
0.orig/
system/
constant/ 中的非 polyMesh 内容
Allrun
Allclean
```

清理 OpenFOAM 算例不会自动删除 `data/` 和 `figures/` 中的分析结果。
