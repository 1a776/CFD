# 不同 N 的运行、画图和收敛性分析命令

本文针对当前项目结构，说明两个案例如何分别运行不同的网格分辨率 `N`，如何生成单个网格的图，如何汇总所有网格的误差并计算观察收敛阶。

当前案例为：

```text
01_sine_wave_quad
    四边形网格 + 一阶迎风：div(phi,T) Gauss upwind

02_sine_wave_quad_linearUpwind
    四边形网格 + linearUpwind：div(phi,T) Gauss linearUpwind grad(T)
```

两个案例的初始函数、速度、定义域、周期边界、终止时间和目标 CFL 相同。它们必须分别收敛分析，不能把一阶迎风和 `linearUpwind` 的误差混在同一张收敛曲线中。

## 2. N 的含义

每个案例按下面的方式组织：

```text
cases/<caseName>/N10/
cases/<caseName>/N20/
cases/<caseName>/N40/
cases/<caseName>/N80/
```

这里的 `N` 表示 $x$ 方向和 $y$ 方向每条边上的单元数。`blockMeshDict` 中的核心设置是：

```text
hex (0 1 2 3 4 5 6 7) (N N 1) simpleGrading (1 1 1)
```

因此：

| 目录 | x 方向单元数 | y 方向单元数 | 总单元数 | 网格尺度 $h$ |
|---|---:|---:|---:|---:|
| `N10` | 10 | 10 | 100 | 0.1 |
| `N20` | 20 | 20 | 400 | 0.05 |
| `N40` | 40 | 40 | 1600 | 0.025 |
| `N80` | 80 | 80 | 6400 | 0.0125 |

`z` 方向始终只有 1 层单元，因为这是二维问题，`zMin` 和 `zMax` 使用 `empty` 边界。

## 3. 只准备不同 N 的算例，不运行求解器

### 3.1 准备 01 案例的四个网格

```bash
python3 scripts/01_sine_wave_quad/run_all_N.py \
    --resolutions 10,20,40,80 \
    --prepare-only \
    --overwrite
```

### 3.2 准备 02 案例的四个网格

```bash
python3 scripts/02_sine_wave_quad_linearUpwind/run_all_N.py \
    --resolutions 10,20,40,80 \
    --prepare-only \
    --overwrite
```

`--prepare-only` 只做以下工作：

1. 以该案例的 `N20` 作为模板；
2. 创建 `N10`、`N40`、`N80` 目录；
3. 复制 `0.orig/`、`system/` 和必要的 `constant/` 文件；
4. 修改 `system/blockMeshDict` 中的 `(N N 1)`；
5. 根据单元中心重新生成 `0.orig/T`；
6. 写入 `Allrun`、`Allclean`、`case.foam` 和 `metadata.json`；
7. 不执行 `blockMesh`、`checkMesh` 或学生求解器。

`--overwrite` 表示目标目录已有内容时允许重建。对 `N20` 使用这个选项时，会先执行 `N20/Allclean`，因此不要在尚未备份重要结果时随意使用。

例如只准备 01 案例的 `N40`：

## 8. 收敛阶是怎样计算的

每个 N 的后处理在最终时间 $t=1$ 计算归一化误差：

$$L_1=rac{\sum_c V_c|T_c-T_c^{exact}|}{\sum_c V_c|T_c^{exact}|}$$

$$L_2=\sqrt{\frac{\sum_c V_c(T_c-T_c^{exact})^2}{\sum_c V_c(T_c^{exact})^2}}$$

$$L_\infty=\frac{\max_c|T_c-T_c^{exact}|}{\max_c|T_c^{exact}|}$$

当网格从 $N$ 加密到 $2N$ 时，对每种误差分别计算观察收敛阶：

$$p=\frac{\log(E_N/E_{2N})}{\log(2)}$$

例如：

```text
observedOrderL1(N20) = log(L1_N10 / L1_N20) / log(2)
observedOrderL1(N40) = log(L1_N20 / L1_N40) / log(2)
observedOrderL1(N80) = log(L1_N40 / L1_N80) / log(2)
```

所以 `N10` 那一行没有前一个更粗网格可比较，`observedOrderL1` 为空是正常的。`N20`、`N40` 和 `N80` 才会分别出现相邻网格的观察阶。

`convergence_summary.csv` 会包含：

```text
resolution
nominalH
normalizedL1
normalizedL2
normalizedLinf
observedOrderL1
observedOrderL2
observedOrderLinf
maxCo
normalizedMassError
finalAmplitude
meshOK
solverEnded
solverFatal
```

## 9. 不同 N 的代码到底哪里不一样

### 9.1 同一个案例内部：主要只有网格和初始场数量不同

例如 01 案例的 `N20` 和 `N40`：

```text
cases/01_sine_wave_quad/N20/system/blockMeshDict
cases/01_sine_wave_quad/N40/system/blockMeshDict
```

二者的关键差异是：

```text
N20: hex (...) (20 20 1) ...
N40: hex (...) (40 40 1) ...
```

于是 `0.orig/T` 中的数值个数也不同：

```text
N20: 20*20 = 400 个标量
N40: 40*40 = 1600 个标量
```

这些数值不是手工随便填的，而是 `scripts/common/advection_tools.py` 中的 `write_initial_field()` 根据单元中心自动生成的：

$$T(x,y,0)=\sin(2\pi(x+y))$$

同一个案例内部，以下设置应该保持一致：

```text
system/controlDict
system/fvSchemes
system/fvSolution
0.orig/U
周期边界定义
终止时间 endTime = 1.0
目标 CFL maxCo = 0.2
```

运行后才生成、可以删除重建的内容包括：

```text
0/
constant/polyMesh/
0.05/、0.10/、...、1/
log.*
postProcessing/
```

### 9.2 两个案例之间：插值格式不同

01 的关键行是：

```text
div(phi,T)      Gauss upwind;
```

02 的关键行是：

```text
div(phi,T)      Gauss linearUpwind grad(T);
```

02 还需要在 `gradSchemes` 中声明：

```text
grad(T)         Gauss linear;
```

除此之外，两个案例应尽量保持相同的网格序列、初始函数、速度、周期边界、CFL 和终止时间，才能把误差差异解释为插值格式造成的差异。

### 9.3 生成 N 的代码位置

批量生成 N 的入口是：

```text
scripts/01_sine_wave_quad/run_all_N.py
scripts/02_sine_wave_quad_linearUpwind/run_all_N.py
```

两个入口都调用：

```text
scripts/common/run_suite.py
```

其中：

| 函数 | 作用 |
|---|---|
| `prepare_case()` | 复制 N20 模板、建立目标 N 目录 |
| `patch_block_mesh()` | 修改 `(N N 1)` |
| `write_initial_field()` | 根据 N 生成 `0.orig/T` |
| `write_case_scripts()` | 写入该 N 的 `Allrun` 和 `Allclean` |
| `run_case()` | 调用 OpenFOAM 的 `Allrun` |

因此你看到每个 N 目录中有很多不同数量的 `T` 数据，本质上是同一个程序在不同网格上的单元值，而不是四套完全不同的求解器代码。

## 11. 如果手动修改插值格式

### 改为一阶迎风

编辑每个目标 N 的：

```text
system/fvSchemes
```

确保存在：

```text
div(phi,T)      Gauss upwind;
```

### 改为 `linearUpwind`

确保存在：

```text
gradSchemes
{
    default         Gauss linear;
    grad(T)         Gauss linear;
}

divSchemes
{
    default         none;
    div(phi,T)      Gauss linearUpwind grad(T);
}
```

如果要让一整个案例的所有 N 使用新格式，最稳妥的流程是：

1. 先修改该案例的 `N20/system/fvSchemes`；
2. 用 `run_all_N.py --prepare-only --overwrite` 重新生成其余 N；
3. 运行所有 N；
4. 重新生成单 N 数据和总体收敛分析。

不要只改 `N20` 却拿旧的 `N10/N40/N80` 和它比较，否则不同 N 使用的格式不一致，收敛阶没有意义。

## 12. 如果修改初始函数、速度或 CFL

### 修改初始函数

当前函数由以下文件控制：

```text
scripts/common/advection_tools.py
```

至少要同步检查：

```text
exact_values()
write_initial_field()
```

因为一个函数负责生成 `0.orig/T`，另一个函数负责生成误差分析所用的精确解。只改初值、不改精确解，会导致误差图失去物理意义。

### 修改速度

需要同步检查：

```text
cases/<caseName>/N20/0.orig/U
scripts/common/advection_tools.py 中 exact_values() 的平移项
```

当前速度是 $(u,v)=(1,1)$，精确解中的相位平移是 $x+y-2t$。如果速度改变为 $(u,v)$，精确解应相应改成 $x-u t+y-v t$ 的形式。

### 修改 CFL 或终止时间

修改每个案例模板中的：

```text
cases/<caseName>/N20/system/controlDict
```

重点检查：

```text
endTime
maxCo
```

如果只修改了 `maxCo`，后处理时要把目标值传给 `plot_results.py`：

```bash
python3 scripts/01_sine_wave_quad/plot_results.py \
    --case-dir cases/01_sine_wave_quad/N40 \
    --target-co 0.1
```

如果修改了模板字典，要重新生成所有 N，确保不同 N 仍使用相同的时间控制规则。

## 14. 关于“第 201 步”

当前目标时间是 `endTime = 1.0`。在 `N20`、目标 `CFL=0.2` 的情况下，理论时间步约为 `0.005`，因此实际推进约 200 步。

检查 CSV 行数：

```bash
wc -l data/cases/01_sine_wave_quad/N20/time_history.csv
```

如果输出是：

```text
201
```

其中第 1 行是 CSV 表头，下面 200 行才是实际时间步，并不表示有第 201 个物理时间步。真正判断时还要检查：

```text
summary.json 中的 timeSteps
summary.json 中的 finalTime
```

最终时间应接近 `1.0`，`timeSteps` 应与求解器日志中完成的时间步数量一致。
