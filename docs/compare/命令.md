## 3. N 的含义

当前结构化四边形网格使用：

```text
hex (0 1 2 3 4 5 6 7) (N N 1) simpleGrading (1 1 1)
```

因此：

| 目录 | x 单元数 | y 单元数 | 总单元数 | 近似网格尺度 |
|---|---:|---:|---:|---:|
| `N10` | 10 | 10 | 100 | 0.1 |
| `N20` | 20 | 20 | 400 | 0.05 |
| `N40` | 40 | 40 | 1600 | 0.025 |
| `N80` | 80 | 80 | 6400 | 0.0125 |

`N` 是每个方向的单元数，不是总单元数。

对三角形案例，`N` 仍表示底面正方形每个方向的基准划分数，但一个
正方形背景单元被切成两个三角形，因此实际 OpenFOAM 棱柱单元数约为
`2*N*N`：

| 目录 | 三角形棱柱单元数 |
|---|---:|
| `N10` | 200 |
| `N20` | 800 |
| `N40` | 3200 |
| `N80` | 12800 |

## 10. 计算收敛阶

```bash
python3 scripts/analyze_study.py \
    --config scripts/configs/01_advection_equation/01_sine_wave_quad_upwind.json
```

脚本读取：

```text
data/01_advection_equation/analysis/01_sine_wave_quad/raw_results.csv
```

并写出：

```text
data/01_advection_equation/analysis/01_sine_wave_quad/convergence_summary.csv
data/01_advection_equation/analysis/01_sine_wave_quad/analysis.md
```

网格误差的计算公式为：

$$L_1=\frac{\sum_c V_c|T_c-T_c^{exact}|}{\sum_c V_c|T_c^{exact}|}.$$

观察收敛阶为：

$$p=\frac{\log(E_N/E_{2N})}{\log(2)}.$$

例如：

```text
observedOrderL1(N20) = log(L1_N10 / L1_N20) / log(2)
observedOrderL1(N40) = log(L1_N20 / L1_N40) / log(2)
observedOrderL1(N80) = log(L1_N40 / L1_N80) / log(2)
```

实际代码位置：

```text
scripts/common/advection_tools.py
    normalized_errors()

scripts/common/study_analysis.py
    observed_order()
    analyse()
```

三角形和四边形使用同一个收敛阶公式。区别只在于三角形后处理使用每个
OpenFOAM 单元自己的体积 `Vc`：

$$L_1=\frac{\sum_c V_c|T_c-T_c^{exact}|}{\sum_c V_c|T_c^{exact}|}.$$

当前已验证的三角形最小烟测结果为：

| N | cells | normalized L1 | L1 order |
|---:|---:|---:|---:|
| 10 | 200 | 9.27033951e-01 | - |
| 20 | 800 | 7.25915357e-01 | 0.352821 |

这个 `N10/N20` 结果只说明 tri 分支能完整跑通并进入收敛分析，不是最终
`N10/N20/N40/N80` 的完整结论。

## 12. 不同 N 的代码哪里不一样

不同 N 的核心区别在：

```text
cases/<caseName>/Nxx/system/blockMeshDict
cases/<caseName>/Nxx/0.orig/T
```

`blockMeshDict` 的核心行：

```text
hex (0 1 2 3 4 5 6 7) (N N 1) simpleGrading (1 1 1)
```

`0.orig/T` 的数据个数等于：

```text
N * N
```

例如：

```text
N20: 400 个标量
N40: 1600 个标量
```

这些值由：

```text
scripts/common/advection_sine.py
scripts/common/advection_tools.py
```

根据单元中心坐标生成：

$$T(x,y,0)=\sin(2\pi(x+y)).$$

不要把 `N20/0.orig/T` 直接复制给 `N40`。

三角形案例不把 `T` 写成固定的 `N*N` 方阵。它必须先生成网格，再读取
OpenFOAM 写出的 `constant/C`，所以：

```text
N10: 200 个标量
N20: 800 个标量
N40: 3200 个标量
```

这些初值由真实 cell centre 计算：

$$T_c=\sin(2\pi(x_c+y_c)).$$

## 13. 不同格式哪里不一样

不同空间格式主要由 JSON 中的：

```text
divScheme
gradTScheme
```

控制。

准备案例时，脚本会把它写入：

```text
cases/<caseName>/Nxx/system/fvSchemes
```

核心实现位置：

```text
scripts/common/foam_case.py
    _patch_fv_schemes()
```

求解器代码中只调用：

```cpp
fvc::div(phi, T, "div(phi,T)")
```

OpenFOAM 会根据 `fvSchemes` 中的 `div(phi,T)` 查找实际格式。

## 14. 修改初始函数、速度或 CFL

### 修改初始函数

正弦波初始场由：

```text
scripts/common/advection_sine.py
```

间接调用：

```text
scripts/common/advection_tools.py
    exact_values()
    write_initial_field()
```

注意：初始场和精确解必须同步修改，否则误差没有意义。

### 修改插值格式

优先修改或新增：

```text
scripts/configs/01_advection_equation/*.json
```

不要手工逐个改每个 N 的 `fvSchemes`，否则容易造成不同 N 使用不同格式。

### 修改 CFL 或终止时间

优先修改 JSON 中的：

```text
maxCo
endTime
```

然后重新准备对应案例：

```bash
python3 scripts/run_study.py \
    --config scripts/configs/01_advection_equation/01_sine_wave_quad_upwind.json \
    --prepare-only \
    --overwrite
```
